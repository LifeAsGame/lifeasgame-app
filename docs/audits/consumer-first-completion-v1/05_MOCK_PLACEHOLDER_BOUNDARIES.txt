LifeAsGame Consumer Mock / Placeholder Boundary Audit

1. PRODUCTION-AUTHORITY FAILURE

Classification: RUNTIME_CONTRACT_GAP

shared/api/client.ts:
  USE_MOCK = process.env.NEXT_PUBLIC_USE_MOCK !== "false"

.env.example:
  NEXT_PUBLIC_USE_MOCK=true

Consequences:
- Missing, misspelled, empty, or unsupported NEXT_PUBLIC_USE_MOCK values select Mock.
- Auth can issue local mock tokens and mutate MOCK_USERS instead of contacting the server.
- Home, Role, LifeLog, Quest, Player, Inventory, Gear, Connections, Direct Chat, Notification, Settings, and Exchange adapters all branch to fixture implementations.
- This is not a silent API-error-to-Mock fallback. The API request is never attempted when the global switch selects Mock.
- Because the default is Mock, demo names, item/quest/achievement records, balances, notifications, chat messages, and mutation results can become apparent runtime authority.

Required correction:
- Default and invalid configuration must select API.
- Mock must require an explicit development/test opt-in.
- Keep existing fixture adapters; they are useful for focused tests and explicit local development once the authority boundary is safe.
- Add a configuration lifecycle test that proves unset/invalid -> API and explicit supported value -> Mock.

2. SILENT FALLBACK CHECK

Classification: VERIFIED

No consumer adapter catch path was found that converts an API error into fixture success. API errors remain errors in API mode. Theme local-cache fallback is intentional preference behavior, not domain-data fallback. Admin uses its independent NEXT_PUBLIC_ADMIN_DATA_SOURCE resolver, where default/invalid -> api and API failure does not fall back to Mock.

Evidence:
- shared/api/client.ts
- features/admin/api/source.ts
- features/admin/api/*source.ts
- Admin source focused tests
